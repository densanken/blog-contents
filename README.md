# blog-contents

[CCSブログ](https://blog.densanken.com) のコンテンツを管理するリポジトリです。\
自分のディレクトリ（`authors/<著者ID>/`）に Markdown ファイルを追加して Pull Request（PR）を送ると、自動チェックを経てブログに公開されます。

> [!NOTE]
> はじめに（投稿のルールについて）
> 対象となる書き手や書いてよい内容など、ブログ全体の運営方針については[投稿ガイドライン](./authors/densanken/posting-guidelines.md)をご確認ください。

## 投稿の流れ

1. **ブランチ作成・ファイル追加**
   リポジトリをフォークし、`authors/<著者ID>/` 配下に記事を追加してください（組織メンバーはフォークせず、このリポジトリに直接ブランチを作成しても構いません）。
   ※はじめて投稿する場合は、`profile.yml` と `meta.yml` もあわせて作成してください。
2. **PR の作成**
   PR のタイトルは必ず **`docs: <概要>`** の形式にしてください（`docs:` で始まらないと自動チェックで弾かれます）。
3. **自動チェックとプレビュー確認**
   不備がある場合は PR にエラー内容がコメントされるので、修正して再度 push してください。すべてのチェックを通過すると、変更した記事のプレビュー URL がコメントされます。
4. **公開（マージ）**
   公開したいタイミングで、PR 本文にある「すべてのチェックが成功したら自動マージする」にチェックを入れましょう。チェック完了後に自動でマージされ、記事が公開されます。

### 投稿時のポイント

- **編集範囲の制限**：変更できるのは自分のディレクトリ（`authors/<著者ID>/`）の中だけです。他人の記事や `authors/` 以外のファイルを変更した PR はマージできません。
- **予約投稿に対応**：`date` に未来の日付を指定した場合も、PR のチェックを通過すればそのままマージできます。記事は指定日以降のサイトビルドで自動的に公開されます。

## ディレクトリ構成と命名ルール

```text
authors/
└─ <著者ID>/
   ├─ profile.yml   # 著者プロフィール（初回必須）
   ├─ meta.yml      # 編集権限の設定（初回必須）
   ├─ hello.md      # 記事ファイル（URL は /hello になります）
   └─ assets/       # 画像置き場（サブディレクトリ作成可）
       └─ image.png
```

ファイルやディレクトリを作る際は、次の命名ルールを守ってください。

- **使える文字**：半角英数字とハイフン（`-`）のみ使用できます。空白やアンダースコア（`_`）は使えないため、スクリーンショットなどはリネームしてから配置しましょう。
- **ピリオドの制限**：ピリオド（`.`）は拡張子の直前に 1 つだけ使えます（`my.post.md` のような名前は不可）。
- **配置場所の制限**：`authors/` 直下には著者ディレクトリしか置けません。記事や設定ファイルは必ず自分の著者ディレクトリの中に入れてください。

## 記事の書き方

記事は著者ディレクトリの直下に小文字の拡張子（`.md`）で作成してください（`assets/` 以外のサブディレクトリは作れません）。\
ファイル名から `.md` を除いた部分が、そのまま記事の URL になります。

使える Markdown 記法の一覧は、[Markdown 構文サンプル](./authors/densanken/markdown-syntax-sample.md)を参考にしてください。

### Frontmatter（記事のメタ情報）

ファイルの先頭に `---` で囲んだ frontmatter を記述し、続けて本文を書いてください。

```markdown
---
title: はじめての記事
date: 2026-01-01
description: 記事の概要をここに書いてください
---

ここから記事の本文を書いてください。
```

指定できる項目は以下の3つのみです。これ以外の項目（`tags` など）は書けません。

| 項目          | 必須か | 指定ルール                                     |
| ------------- | ------ | ---------------------------------------------- |
| `title`       | 必須   | 1〜300文字                                     |
| `date`        | 必須   | 公開日。実在する日付を `YYYY-MM-DD` 形式で指定 |
| `description` | 任意   | 記事の概要。指定する場合は 1〜1000文字         |

### 画像の載せ方

画像は同じ著者の `assets/` 内に配置し、記事から相対パスで参照してください（`assets/` の中にサブディレクトリを作ることも可能です）。

```markdown
![画像の説明](./assets/image.png)
```

- **対応フォーマット**：PNG / JPEG / GIF / WebP / AVIF（※SVG は非対応）
- **配置ルール**：`assets/` の中には画像ファイルのみ配置できます。また、画像を `assets/` の外に置くこともできません。
- **未使用画像も検査対象**：記事から参照されていない画像であっても、容量や形式の自動チェック対象になります。不要な画像は削除しておきましょう。

## プロフィールと編集者の設定

はじめて投稿する際は、著者ディレクトリ直下に `profile.yml` と `meta.yml` を作成してください（拡張子は `.yaml` でも構いませんが、どちらか一方のみ置いてください）。

### 1. `profile.yml`（著者情報の登録）

ブログの著者ページに表示される情報です。必須項目は `name` のみで、ここに記載した以外の項目は指定できません。

```yaml
name: 表示名
github: example
x: example
website: https://example.com
icon: assets/icon.png
bio: 自己紹介
admissionYear: 2024
pinned:
  - hello
  - second-post
```

| 項目            | 指定ルール                                                                                                                               |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `name`          | **【必須】** 1〜100文字                                                                                                                  |
| `github`        | GitHub のユーザー名                                                                                                                      |
| `x`             | X のユーザー名（`@` なし、英数字と `_` で15文字以内）。`twitter` でも指定可                                                              |
| `website`       | **【組織メンバーのみ可】** ユーザー名やパスワードを含まない `https://` の URL（200文字以内）                                             |
| `icon`          | `https://` の URL、または `assets/` から始まる画像への相対パス（相対パスの場合は画像の実在が必要）                                       |
| `bio`           | 1〜500文字                                                                                                                               |
| `admissionYear` | 入学年度（半角数字で4文字以内）                                                                                                          |
| `pinned`        | 著者ページに固定表示する記事の配列。拡張子 `.md` を除いたファイル名を最大3件まで指定可（重複・存在しない記事は不可／大小文字は区別なし） |

### 2. `meta.yml`（編集権限の指定）

この著者ディレクトリを編集できる人を指定するファイルです（**必須**・ブログ上には表示されません）。\
GitHub ユーザー名、または `team:` に続けて GitHub チームの slug を1つ以上指定してください。`editors` 以外の項目は書けません。

```yaml
editors:
  - example
  - team:team-a
```

## PR チェックで弾かれる条件（リファレンス）

PR を送ると、ブログ本体のビルドを含めた厳格な自動検査が走ります。\
失敗した場合は `<ファイルのパス>: <理由と直し方>` の形式でコメントが届くので、以下の表を参考に修正してください。

### ファイルとディレクトリ

| エラーになる条件                                                             | 対処法                                  |
| ---------------------------------------------------------------------------- | --------------------------------------- |
| 名前に半角英数字とハイフン（`-`）以外を使っている                            | 使える文字だけの名前に変更する          |
| `assets/` 以外のサブディレクトリがある（`notes/draft.md` など）              | 記事を著者ディレクトリの直下に移す      |
| 記事のファイル名にピリオドが含まれている（`my.post.md` など）                | ハイフンなどに置き換える                |
| 大文字と小文字だけが異なる名前が同じ場所にある（`Hello.md` と `hello.md`）   | どちらかのファイル名を変更する          |
| 記事のファイル名が `page.md`、または著者 ID が `page` になっている           | 別の名前に変更する                      |
| 拡張子が `.md` / `.yaml` / `.yml` / 対応画像以外                             | 該当ファイルを削除する                  |
| 記事の拡張子に大文字が含まれている（`.MD` など）                             | 小文字の `.md` に変更する               |
| YAML ファイルが `profile` と `meta` 以外、または著者ディレクトリ直下にない   | 削除するか正しい場所に移動する          |
| 空のディレクトリ、または Git のサブモジュールが含まれている                  | 削除する                                |
| シンボリックリンクが含まれている                                             | 実体のファイルに置き換える              |
| `profile` と `meta` が1つずつ揃っていない（または `.yml` と `.yaml` が重複） | どちらか一方の拡張子で 1 つずつ用意する |
| 画像以外が `assets/` 内にある、または画像が `assets/` 外にある               | 正しい配置場所に移動する                |
| 画像以外のファイルサイズが2MiB を超えている                                  | 内容を減らすか、ファイルを分割する      |

### 記事と YAML の構文

| エラーになる条件                                               | 対処法                           |
| -------------------------------------------------------------- | -------------------------------- |
| 記事の文字数が500,000文字を超えている                          | 短くするか、複数の記事に分割する |
| ファイルの先頭に `---` で囲んだ frontmatter がない             | 先頭に frontmatter を記述する    |
| frontmatter や YAML の構文が不正、または同じキーが重複している | YAML の書式を正しく修正する      |
| 未対応の項目名が含まれている（`tags` など）                    | 未対応の項目を削除する           |
| 各項目の値が、文字数や形式の条件を満たしていない               | 前述の仕様表を確認して修正する   |

### 画像の仕様（実体検査）

拡張子だけでなく画像データの中身も検査されます（上限値の正確な定義は [scripts/content/image.ts](./scripts/content/image.ts) を参照）。

| エラーになる条件                                                      | 対処法                       |
| --------------------------------------------------------------------- | ---------------------------- |
| ファイルサイズが10,000,000バイト（10MB）を超えている                  | リサイズや圧縮で容量を減らす |
| 画素数が50,000,000（5,000万画素）を超えている                         | 画像を縮小する               |
| アニメーションが200フレームを超える、または全フレームの総画素数が多い | フレーム数を減らす           |
| 拡張子と実際の画像形式が一致していない（PNG を `.jpg` にしている等）  | 正しい拡張子にリネームする   |
| 画像データが破損していて展開できない                                  | 画像を書き出し直す           |

### 書式フォーマットとその他のチェック

- **フォーマットの一致**：Markdown と YAML は、整形ツール（oxfmt）の出力と完全に一致している必要があります。インデントや空行、表の桁揃えのズレでも失敗するため、ローカルで `pnpm fmt` を実行して整えてください。
- **PR タイトル**：`docs:` で始まっている必要があります。
- **ウイルス検査**：ClamAV によるスキャンでウイルスが検出された場合や検査エラー時は失敗します。
- **ブログ本体のビルド**：[densanken/blog](https://github.com/densanken/blog) の `main` に PR をマージした状態で、予約投稿を含めて厳格モードでビルドを行います。記事が除外されるような不備があると失敗します。
- **ビルド出力容量**：サイト全体の出力が **750MB を超えると警告**、**950MB を超えるとエラー**になります。画像を圧縮するか点数を減らしてください。

## ローカル環境での事前チェック

PR を出す前に、手元の環境で自動検査と同じチェックを実行できます。\
動作には Node.js と pnpm が必要です。

### 1. 環境構築（mise を使う場合・任意）

バージョン管理ツール [mise](https://mise.jdx.dev/) を使うと、指定バージョンの Node.js と pnpm をまとめて導入できます。

```sh
mise trust   # 初回のみ：このリポジトリの設定を信頼する
mise install # .nvmrc と package.json に基づいてツールを導入
```

導入後、`node -v` と `pnpm -v` でバージョンが表示されれば準備完了です（切り替わらない場合はシェルで `mise activate` が有効か確認してください）。

### 2. 依存関係のインストールと検査コマンド

```sh
pnpm install
```

`pnpm install` を実行すると Git フックが自動で設定され、コミット時にステージ済みのファイルが自動整形されます。手動で確認・整形したい場合は以下のコマンドを使用してください。

| コマンド             | 役割                                                       |
| -------------------- | ---------------------------------------------------------- |
| `pnpm check:content` | `authors/` の構成・記事・画像・YAML のルールを検査します   |
| `pnpm fmt:check`     | 書式整形（フォーマット）が必要なファイルがないか確認します |
| `pnpm fmt`           | Markdown や YAML の書式を自動で整形します                  |
| `pnpm check`         | 型検査・lint・書式確認をまとめて実行します                 |

> [!TIP]
> ローカルで `pnpm check:content` と `pnpm fmt:check` の両方が通れば、ブログ本体のビルドとウイルス検査以外のチェックはすべて通過します。
